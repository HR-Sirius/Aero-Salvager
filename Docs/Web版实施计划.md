# 浮空回收求解器网站实施计划

## 1. 项目目标

将 `aerosalvager.cpp` 中的 C++ 算法重写为 TypeScript，并使用 Vite + React + TypeScript 构建一个网页应用。用户可以在网页上：

- 选择 N（3 / 5 / 7）
- 在 N×N 网格中点击设置“允许挂载气球”的坐标
- 输入 M
- 输入浮力 1~6 的气球数量
- 点击求解
- 在同一个网格中查看分配结果或“无解”
- 结果网格中用颜色和数字区分不同浮力的气球

## 2. 技术栈

- Vite
- React
- TypeScript
- Web Worker
- 样式方案待定，建议使用 CSS Modules 或普通 CSS

## 4. 坐标系统与网格映射

- 中心格坐标为 `(0, 0)`
- x 轴向右为正
- y 轴向上为正
- N 为奇数，预设值为 3、5、7
- 屏幕行列到算法坐标的映射：
  - `x = col - (N - 1) / 2`
  - `y = (N - 1) / 2 - row`
- 以 N = 5 为例：
  - 左上角：`(-2, 2)`
  - 中心格：`(0, 0)`
  - 右下角：`(2, -2)`

## 5. 数据模型

### 5.1 输入数据

- `coordinate: [number, number][]`
  - 每个元素为 `[x, y]`
  - 只包含用户点击选中的“允许挂载”坐标
- `balloonType: [number, number][]`
  - 每个元素为 `[浮力, 数量]`
  - 数量为 0 的种类在传给算法前过滤掉
- `M: number`
  - 用户输入的预期总浮力

### 5.2 算法内部数据

- `assignment: number[]`
  - 长度与 `coordinate` 相同
  - `0` 表示该位置未分配气球
  - 非 0 表示该位置分配的浮力值
- `T_x`、`T_y`
  - 当前已分配气球产生的 x、y 方向力矩和
- `xOrder`、`yOrder`
  - 按 x、y 坐标升序排序后的坐标索引数组

### 5.3 页面状态

- 编辑模式 / 结果模式 / 求解中
- 当前 N
- 当前 M
- 当前允许挂载坐标集合
- 当前气球数量
- 当前求解结果
- 当前是否无解
- 当前是否正在求解

## 6. UI 布局

- 左侧：操作提示区
- 中间：
  - 网格上方：N 选择器、M 输入框
  - 网格区域：N×N 方格
- 右侧：
  - 气球种类列表：浮力 1~6 的图标与数量输入
  - 列表下方：求解按钮、返回编辑/重置按钮

## 7. 交互规则

- 初始所有格子不可挂载。
- 点击格子切换“允许挂载 / 不允许挂载”。
- 修改 N 时，保留在新 N 范围内仍然有效的已选坐标。
- 修改任何输入后，立刻清空结果区域。
- 总浮力不等于 M 时，求解按钮禁用。
- 求解中，求解按钮文字变为“求解中...”，并保持禁用，直到求解完成。
- 求解完成后，如果成功，网格切换到结果模式并显示分配。
- 如果无解，网格区域显示“无解”。
- 结果模式下点击格子无效。
- 必须点击“返回编辑/重置”才能回到编辑模式。
- 返回编辑模式时，只清空结果，保留 N、M、允许挂载坐标、气球数量等输入。
- 编辑模式下，“返回编辑/重置”按钮显示但禁用。

## 8. 结果可视化

- 使用同一个网格切换显示结果。
- 已分配气球的格子不改变格子本身颜色，而是在其上渲染对应气球的图标。
- 气球图标颜色从浅白色到橙红色：
  - 浮力 1：最浅，接近白色
  - 浮力 6：最深，橙红色
- 右侧气球面板中的图标也使用同一套颜色。
- 三种格子状态样式不同：
  - 不可挂载
  - 允许挂载但未使用
  - 已分配气球

## 9. Web Worker 通信

- 创建一个长期存在的 Web Worker。
- 主线程向 Worker 发送：
  - `{ balloonType: [浮力, 数量][], coordinate: [x, y][], M: number }`
- Worker 向主线程返回：
  - `{ success: boolean, assignment: number[] | null }`
- 只返回 `success` 和 `assignment`。
- 求解过程中禁用求解按钮，避免重复提交。

## 10. 算法翻译计划

- 在 `src/algorithm` 目录下实现 TypeScript 版本。
- 保留上下界剪枝 `Cur_UL_Bounds`，采用放宽版本（A）。
- 保留外层 DFS 和内层 DFS 的整体结构。
- 只要求找到一个可行解，不要求与 C++ 输出完全一致。
- 每次求解时，确保算法内部状态重置，避免上一次求解残留。
- 可以优化排序、剪枝和状态管理，但核心搜索逻辑保持清晰。
- 使用 `main.cpp` 中的两个例子做单元测试：
  - 至少能找到一个可行解
  - 解满足力矩平衡
  - 每个允许挂载格子最多一个气球

## 11. 组件划分建议

- `App`：全局状态、模式切换、Worker 管理
- `Grid`：渲染 N×N 网格
- `Cell`：单格点击与显示
- `BalloonTypePanel`：右侧气球列表、数量输入
- `ControlPanel`：N 选择器、M 输入
- `ActionButtons`：求解、返回编辑/重置
- `solver.worker.ts`：Web Worker 入口
- `solver.ts`：TypeScript 算法实现
- `types.ts`：共享类型定义
- 状态管理建议使用 `useState` 或 `useReducer`
